# cli-switch v2.0 概要设计

> 版本：v2.0 | 更新日期：2026-04-10

## 1. 架构总览

v2.0 采用 4 层架构，核心原则：**Adapter 隔离 + Profile 显式建模 + JSON-First**。

```
┌─────────────────────────────────────────────────┐
│                   CLI Layer                      │
│  参数解析 · 结果渲染 · 错误码 · 退出码          │
│  (无工具特定逻辑)                                │
├─────────────────────────────────────────────────┤
│               Core Resolver Layer                │
│  RequestNormalizer · ProfileSelector             │
│  ModelResolver · RuntimeBuilder                  │
│  DiagnosticAggregator                            │
├─────────────────────────────────────────────────┤
│                Adapter Layer                     │
│  ClaudeAdapter · GeminiAdapter                   │
│  CodexAdapter · OpenCodeAdapter                  │
│  (每工具一个，统一抽象接口)                      │
├─────────────────────────────────────────────────┤
│               Registry Layer                     │
│  ModelRegistry · ProviderRegistry                │
│  ProfileRegistry · CapabilityRegistry            │
│  (配置驱动，YAML 加载)                           │
└─────────────────────────────────────────────────┘

横切关注点（跨层服务）:
┌─────────────────────────────────────────────────┐
│  Session（终端隔离） · FileLocker（并发安全）     │
│  Hooks（事件引擎）   · MCP（Server 管理）         │
│  ErrorDiagnostics（错误诊断）                     │
└─────────────────────────────────────────────────┘
```

## 2. 各层职责

### 2.1 CLI Layer（表现层）

**职责**：参数解析、结果渲染、退出码管理。

- 使用 argparse 解析命令和参数
- 根据 `--json` 标志选择 JSON / 文本渲染
- 统一退出码：0=成功，1=一般错误，2=参数错误，3=配置错误
- **禁止**包含任何工具特定逻辑

**模块**：
- `main.py` — 命令路由分发
- `renderer.py`（新增）— 文本/JSON 输出渲染

### 2.2 Core Resolver Layer（核心层）

**职责**：输入标准化、Profile 选择、模型解析、运行时规格构建。

**模块**：
| 模块 | 职责 |
|-----|------|
| `RequestNormalizer` | 用户输入标准化（模型别名、工具名规范化） |
| `ProfileSelector` | 根据 --profile / --tool / 默认值选择 Profile |
| `ModelResolver` | Profile + 模型名 → 最终 Model 对象 |
| `RuntimeBuilder` | Model + Auth + Command → RuntimeSpec |
| `DiagnosticAggregator` | 收集各层诊断信息，组装 doctor 输出 |

**处理流 — resolve**：
```
用户输入 → RequestNormalizer → ProfileSelector → ModelResolver
    → Adapter.resolve_model()
    → Adapter.resolve_auth()
    → Adapter.build_command()
    → RuntimeBuilder → RuntimeSpec JSON
```

**处理流 — auth status**：
```
用户输入 → RequestNormalizer → ProfileSelector
    → Adapter.resolve_auth()
    → AuthInspector（检查 env → config → native store → fallback）
    → AuthResult JSON
```

**处理流 — doctor**：
```
用户输入 → RequestNormalizer
    → Platform checks（binary_found, version_readable）
    → Registry validation（model_valid, profile_exists）
    → Adapter.doctor_checks()
    → DiagnosticAggregator → DoctorReport JSON
```

### 2.3 Adapter Layer（适配层）

**职责**：封装各 AI CLI 工具的差异，提供统一抽象接口。

每个 Adapter 实现 7 个方法（详见详细设计文档）：
1. `resolve_model(key) → Model`
2. `resolve_auth(profile, env, config) → AuthResult`
3. `build_command(runtime_spec) → CommandSpec`
4. `doctor_checks(profile) → List[DiagnosticResult]`
5. `get_capabilities(profile) → Capabilities`
6. `get_transport_policy(profile) → TransportPolicy`
7. `validate_profile(profile) → ValidationResult`

**Adapter 清单**：
| Adapter | 工具 | 配置文件 | 认证模式 |
|---------|-----|---------|---------|
| ClaudeAdapter | Claude Code | ~/.claude/settings.json | api_key, login |
| GeminiAdapter | Gemini CLI | ~/.gemini/config.json | api_key, login |
| CodexAdapter | Codex CLI | ~/.codex/config.toml | api_key |
| OpenCodeAdapter | OpenCode | ~/.opencode/config.yaml | api_key |

### 2.4 Registry Layer（注册层）

**职责**：管理模型、供应商、Profile、能力等元数据。配置驱动，YAML 加载。

**Registry 类型**：
| Registry | 数据源 | 说明 |
|---------|-------|------|
| ModelRegistry | default_models.yaml + custom_models.yaml | 模型元数据（key, model_id, vendor, transport） |
| ProviderRegistry | providers.yaml | 供应商信息（id, auth_modes, endpoints） |
| ProfileRegistry | profiles.yaml + user profiles | Profile 定义（tool, auth_mode, capabilities） |
| CapabilityRegistry | 内嵌于 Profile/Model | 能力声明（mcp, skills, streaming 等） |

**配置合并策略**：对象级合并（object-granule merge）
- 用户自定义配置 > 内置默认配置
- Profile 级覆盖 > 工具级默认 > 全局默认

## 3. 依赖规则

```
✅ 允许的依赖方向：
  CLI → Core → Registry
  CLI → Core → Adapter Interface
  Adapter → Registry
  Adapter → Platform（文件系统/环境变量）
  横切服务 → 任意层（通过依赖注入）

❌ 禁止的依赖：
  Registry → Adapter（Registry 不知道 Adapter 存在）
  CLI → 具体 Adapter（CLI 只通过 Core 间接调用）
  Adapter → CLI Renderer（Adapter 不负责输出格式）
  Core → 具体 Adapter（Core 只依赖 Adapter 接口）
```

## 4. 核心数据结构

### 4.1 RuntimeSpec（resolve 输出）

```
RuntimeSpec
├── schema_version: str          # "2.0.0"
├── tool: str                    # "claude-code"
├── profile: str                 # "default"
├── model: Model
│   ├── key: str                 # "opus4.6"
│   ├── model_id: str            # "claude-opus-4-6-20250514"
│   ├── vendor: str              # "fucheers"
│   └── transport: str           # "anthropic-compatible"
├── provider: Provider
│   ├── id: str
│   ├── display_name: str
│   └── auth_mode: str
├── auth: AuthResult
│   ├── mode: str                # api_key|login|oauth|none
│   ├── status: str              # ready|missing|expired|conflict|unsupported|unknown
│   ├── source: str
│   └── hint: Optional[str]
├── command: CommandSpec
│   ├── program: str
│   ├── args: List[str]
│   └── env_patch: Dict[str, str]
├── capabilities: Capabilities
│   ├── mcp: bool
│   ├── skills: bool
│   ├── streaming: bool
│   ├── image_input: bool
│   ├── structured_output: bool
│   └── non_interactive: bool
└── diagnostics: List[Diagnostic]
```

### 4.2 Profile

```
Profile
├── tool: str                    # "claude-code"
├── name: str                    # "default"
├── description: str
├── auth_mode: str               # api_key|login|oauth|none
├── vendor: str
├── transport: str
├── capabilities: Capabilities
├── env_override: Dict[str, str] # 环境变量覆盖
└── command_template: Optional[CommandTemplate]
```

## 5. 横切关注点

### 5.1 Session（终端隔离）
- 保留 v1.2.0 设计：TTY 级别 Session + PID 验证
- v2.0 扩展：Session 中记录当前 Profile

### 5.2 FileLocker（并发安全）
- 保留 v1.2.0 设计：per-tool fcntl flock + 原子写
- v2.0 扩展：per-profile 锁（如需要）

### 5.3 Hooks（事件引擎）
- 保留 v1.2.0 设计：post_switch / pre_tool_use / post_tool_use
- v2.0 扩展：新增 post_resolve hook 类型

### 5.4 MCP（Server 管理）
- 保留 v1.2.0 全部功能
- v2.0 扩展：MCP 配置随 Profile 切换

### 5.5 ErrorDiagnostics（错误诊断）
- 重构 v1.2.0 的 ErrorType 枚举 → 统一 8 类错误码
- 所有错误包含 error_code + message + hint
