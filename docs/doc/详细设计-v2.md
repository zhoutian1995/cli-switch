# cli-switch v2.0 详细设计

> 版本：v2.0 | 更新日期：2026-04-10

## 1. Adapter 协议

所有 Adapter 必须继承 `BaseAdapter` 并实现以下 7 个方法：

### 1.1 接口定义

```python
from abc import ABC, abstractmethod
from typing import List, Optional, Dict

class BaseAdapter(ABC):
    """AI CLI 工具适配器基类"""

    @abstractmethod
    def resolve_model(self, key: str) -> Model:
        """模型名称 → Model 对象
        
        Args:
            key: 模型键名（如 "opus4.6"）
        Returns:
            Model 对象（含 model_id, vendor, transport）
        Raises:
            ModelNotFoundError: 模型不存在
        """

    @abstractmethod
    def resolve_auth(
        self, profile: Profile, env: Dict[str, str], config: Dict
    ) -> AuthResult:
        """解析认证状态
        
        检查顺序：env → config file → native store → adapter fallback
        
        Args:
            profile: 当前 Profile
            env: 环境变量字典
            config: 配置文件内容
        Returns:
            AuthResult（mode, status, required, detected, hint）
        """

    @abstractmethod
    def build_command(self, runtime_spec: RuntimeSpec) -> CommandSpec:
        """构建启动命令
        
        Args:
            runtime_spec: 运行时规格
        Returns:
            CommandSpec（program, args, env_patch）
        """

    @abstractmethod
    def doctor_checks(self, profile: Profile) -> List[DiagnosticResult]:
        """执行健康检查
        
        Returns:
            诊断结果列表，每项含 name, status(pass/fail/skip), detail, hint
        """

    @abstractmethod
    def get_capabilities(self, profile: Profile) -> Capabilities:
        """获取能力声明
        
        Returns:
            Capabilities（mcp, skills, streaming, image_input 等）
        """

    @abstractmethod
    def get_transport_policy(self, profile: Profile) -> TransportPolicy:
        """获取传输策略
        
        Returns:
            TransportPolicy（base_url, timeout, retry_policy）
        """

    @abstractmethod
    def validate_profile(self, profile: Profile) -> ValidationResult:
        """验证 Profile 配置合法性
        
        Returns:
            ValidationResult（valid: bool, errors: List[str]）
        """
```

### 1.2 各 Adapter 实现要点

#### ClaudeAdapter
- 配置文件：`~/.claude/settings.json`
- 认证：`ANTHROPIC_AUTH_TOKEN`（env） / `~/.claude/.credentials.json`（native store）
- 命令：`claude` 二进制
- 环境变量：`ANTHROPIC_MODEL`, `ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`
- 特殊能力：MCP、skills、tool_policy

#### GeminiAdapter
- 配置文件：`~/.gemini/config.json`
- 认证：`GEMINI_API_KEY`（env） / `gcloud auth`（login）
- 命令：`gemini` 二进制
- 环境变量：`GEMINI_MODEL`, `OPENROUTER_BASE_URL`（兼容模式）
- 特殊能力：图片生成（Imagen）

#### CodexAdapter
- 配置文件：`~/.codex/config.toml`
- 认证：`OPENAI_API_KEY`（env）
- 命令：`codex` 二进制
- 环境变量：`OPENAI_MODEL`, `OPENAI_BASE_URL`, `OPENAI_API_KEY`
- 注意：TOML 编辑使用 toml 库替代正则（修复 v1.2.0 的脆弱性）

#### OpenCodeAdapter（v2.0 新增）
- 配置文件：`~/.opencode/config.yaml`
- 认证：`OPENCODE_API_KEY`（env）
- 命令：`opencode` 二进制
- 环境变量：待定义

## 2. 核心数据结构

### 2.1 Model

```python
@dataclass
class Model:
    key: str              # 唯一键名，如 "opus4.6"
    model_id: str         # 供应商模型 ID，如 "claude-opus-4-6-20250514"
    display_name: str     # 显示名称
    vendor: str           # 供应商标识，如 "fucheers", "google", "zhipu"
    transport: str        # 传输协议，如 "anthropic-compatible", "google-ai"
    tools: List[str]      # 支持的工具列表，如 ["claude-code", "gemini-cli"]
    description: str = "" # 模型描述
    source: str = "builtin"  # 来源：builtin / custom
```

### 2.2 Provider

```python
@dataclass
class Provider:
    id: str                    # 如 "fucheers", "google", "zhipu"
    display_name: str          # "Fucheers", "Google", "智谱"
    auth_modes: List[str]      # ["api_key"], ["api_key", "login"]
    base_url: Optional[str]    # API 基础 URL
    schema_version: str = "2.0.0"
```

### 2.3 Profile

```python
@dataclass
class Profile:
    tool: str              # "claude-code"
    name: str              # "default"
    description: str       # "默认 Claude Code 配置"
    auth_mode: str         # "api_key"
    vendor: str            # "fucheers"
    transport: str         # "anthropic-compatible"
    capabilities: Capabilities
    env_override: Dict[str, str] = field(default_factory=dict)
    command_template: Optional[CommandTemplate] = None

    @property
    def full_name(self) -> str:
        return f"{self.tool}/{self.name}"
```

### 2.4 RuntimeSpec

```python
@dataclass
class RuntimeSpec:
    schema_version: str     # "2.0.0"
    tool: str
    profile: str
    model: Model
    provider: Provider
    auth: AuthResult
    command: CommandSpec
    capabilities: Capabilities
    diagnostics: List[Diagnostic] = field(default_factory=list)

    def to_json(self) -> dict:
        """序列化为 JSON-safe 字典，自动脱敏"""
        ...
```

### 2.5 AuthResult

```python
@dataclass
class AuthResult:
    mode: str       # api_key | login | oauth | none
    status: str     # ready | missing | expired | conflict | unsupported | unknown
    required: List[str]           # 需要的凭据名
    detected: List[AuthSource]    # 检测到的凭据源
    source: Optional[str] = None  # 最终使用的凭据来源
    hint: Optional[str] = None    # 修复建议

@dataclass
class AuthSource:
    source: str     # "env:ANTHROPIC_AUTH_TOKEN", "file:~/.claude/.credentials.json"
    status: str     # "valid", "expired", "malformed"
```

### 2.6 CommandSpec

```python
@dataclass
class CommandSpec:
    program: str              # 二进制路径，如 "/usr/local/bin/claude"
    args: List[str] = field(default_factory=list)
    env_patch: Dict[str, str] = field(default_factory=dict)

    def preview(self) -> str:
        """生成预览命令字符串（脱敏）"""
        ...
```

### 2.7 Capabilities

```python
@dataclass
class Capabilities:
    mcp: bool = False
    skills: bool = False
    tool_policy: bool = False
    streaming: bool = True
    image_input: bool = False
    structured_output: bool = False
    non_interactive: bool = True
```

### 2.8 DiagnosticResult

```python
@dataclass
class DiagnosticResult:
    name: str       # "binary_found", "auth_ready"
    status: str     # "pass", "fail", "skip"
    detail: str     # 详细信息
    hint: Optional[str] = None  # 修复建议
```

## 3. resolve 处理流

### 3.1 优先级规则

```
CLI 参数（--model, --tool, --profile） 
  > Profile 默认值
  > 工具默认值
  > Registry fallback
```

### 3.2 详细流程

```
1. CLI Layer 解析参数 → ResolveRequest(model, tool, profile, json_mode)
2. RequestNormalizer:
   - 模型别名展开（如 "opus" → "opus4.6"）
   - 工具名规范化（如 "claude" → "claude-code"）
3. ProfileSelector:
   - 如果指定 --profile → 使用指定 Profile
   - 如果指定 --tool → 使用该工具的 default Profile
   - 否则 → 使用全局 active Profile（Session 记录）
4. ModelResolver:
   - Registry 查询模型
   - 验证模型与 Profile 工具兼容
5. Adapter 调用:
   - adapter.resolve_model(key) → Model
   - adapter.resolve_auth(profile, env, config) → AuthResult
   - adapter.build_command(partial_spec) → CommandSpec
   - adapter.get_capabilities(profile) → Capabilities
6. RuntimeBuilder:
   - 组装 RuntimeSpec
   - 注入 schema_version
   - 脱敏处理（env_patch 中的 token）
7. 返回 RuntimeSpec JSON
```

## 4. auth status 处理流

### 4.1 检查源顺序

```
1. 环境变量（最高优先级）
   - ANTHROPIC_AUTH_TOKEN / GEMINI_API_KEY / OPENAI_API_KEY
2. 配置文件
   - ~/.config/cli-switch/config.yaml 中的 auth 段
3. 原生存储
   - ~/.claude/.credentials.json（Claude）
   - gcloud 登录态（Gemini）
4. Adapter 特定 fallback
   - 各 Adapter 自定义的认证发现逻辑
```

### 4.2 状态判定规则

| 场景 | 状态 |
|-----|------|
| 找到有效凭据 | `ready` |
| 未找到任何凭据 | `missing` |
| 找到但已过期（JWT exp < now） | `expired` |
| 找到多个不同来源的冲突凭据 | `conflict` |
| 工具不支持该认证模式 | `unsupported` |
| 无法判定 | `unknown` |

## 5. 错误处理

### 5.1 统一错误模型

```python
@dataclass
class CLISwitchError:
    error_code: str          # "CONFIG_NOT_FOUND"
    message: str             # 人类可读描述
    hint: Optional[str]      # 修复建议
    detail: Optional[dict]   # 结构化详情（仅 JSON 模式）

    def to_json(self) -> dict:
        return {
            "schema_version": "2.0.0",
            "error": {
                "code": self.error_code,
                "message": self.message,
                "hint": self.hint,
                "detail": self.detail,
            }
        }
```

### 5.2 错误处理原则

1. 所有失败有错误码，不输出裸文本
2. 不暴露 panic / traceback 给用户
3. 敏感信息自动脱敏：`sk-abcdefghijklmnop` → `sk-****mnop`
4. JSON 模式和文本模式共享同一错误模型
5. 每个错误尽量附带 hint（修复建议）

## 6. 配置系统

### 6.1 配置格式

v2.0 保持 YAML 格式（v1 兼容），长期计划迁移 TOML。

### 6.2 配置路径

```
XDG 标准路径:
~/.config/cli-switch/
├── config.yaml          # 主配置
├── profiles.yaml        # Profile 定义
├── custom_models.yaml   # 自定义模型
└── hooks.yaml           # Hook 配置

运行时数据:
~/.local/share/cli-switch/
├── sessions/            # TTY Session 文件
├── locks/               # flock 文件
└── health_status.json   # 健康检查缓存

缓存:
~/.cache/cli-switch/
└── ...
```

### 6.3 配置合并

对象级合并（object-granule merge）：
```
最终配置 = 内置默认 ← 全局用户配置 ← Profile 配置 ← CLI 参数
```

数组不合并，后者整体替换前者。

## 7. 平台处理

### 7.1 路径解析

| 平台 | XDG_CONFIG_HOME 默认 | XDG_DATA_HOME 默认 |
|-----|--------------------|--------------------|
| Linux | `~/.config` | `~/.local/share` |
| macOS | `~/.config`（XDG 优先）→ `~/Library/Application Support`（fallback） | 同上 |

### 7.2 平台差异封装

```python
class Platform:
    @staticmethod
    def config_dir() -> Path: ...
    
    @staticmethod
    def data_dir() -> Path: ...
    
    @staticmethod
    def cache_dir() -> Path: ...
    
    @staticmethod
    def which(binary: str) -> Optional[Path]: ...
```

平台差异仅在 Platform 类中处理，其他模块调用 Platform 接口。

## 8. 脱敏规则

| 类型 | 规则 | 示例 |
|-----|------|------|
| API Key | 保留前缀 + 最后 4 字符 | `sk-****abcd` |
| Bearer Token | 保留前 6 + 最后 4 | `Bearer ey****wxyz` |
| URL 中的 token | 完全替换 | `https://api.example.com?token=****` |
| 文件路径 | 不脱敏 | `~/.claude/.credentials.json` |

脱敏在 RuntimeSpec.to_json() 中统一处理，不散落在各模块。
