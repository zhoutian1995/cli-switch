# cli-switch v1 → v2 迁移指南

> 更新日期：2026-04-10

## 1. 概述

cli-switch v2.0 引入了 4 层 Adapter 架构、Profile 系统和标准化 JSON 输出。本指南帮助 v1.x 用户平滑迁移。

**核心变化**：
- 新增 `resolve`、`auth status`、`doctor` 命令
- 引入 Profile 多运行模式
- 所有 JSON 输出包含 `schema_version`
- 部分 v1 命令标记为废弃（仍可用，v2.1 移除）

## 2. 命令映射

### 2.1 新增命令

| v2.0 新命令 | 用途 | v1 对应 |
|------------|------|---------|
| `cli-switch resolve [model] --json` | 标准化运行时规格输出 | `cli-switch env`（功能更弱） |
| `cli-switch auth status --json` | 认证状态诊断 | `cli-switch status`（无 auth 诊断） |
| `cli-switch doctor --json` | 统一健康检查 | `cli-switch validate` + `cli-switch health-check` |
| `cli-switch doctor --network` | 含网络检查的健康诊断 | `cli-switch test` |

### 2.2 废弃命令

以下命令在 v2.0 中仍可使用，但会输出废弃警告。计划 v2.1 移除。

| v1 命令 | 废弃原因 | 迁移到 |
|--------|---------|-------|
| `cli-switch status` | 功能被 `auth status` 取代 | `cli-switch auth status` |
| `cli-switch validate` | 功能合并到 `doctor` | `cli-switch doctor` |
| `cli-switch health-check` | 功能合并到 `doctor` | `cli-switch doctor --network` |
| `cli-switch test` | 功能合并到 `doctor` | `cli-switch doctor --network` |

### 2.3 保留命令（无变化）

以下命令完全向后兼容：

```
cli-switch <model>        # 切换模型
cli-switch env <model>    # Agent 模式环境变量
cli-switch list           # 列出模型（增加 Profile 信息）
cli-switch model *        # 自定义模型管理
cli-switch mcp *          # MCP 管理
cli-switch hook *         # Hook 管理
cli-switch image          # 图片生成
cli-switch chat-test      # 端到端测试
cli-switch config *       # 配置管理
```

## 3. 配置迁移

### 3.1 配置文件变化

| 文件 | v1.x 位置 | v2.0 位置 | 变化 |
|-----|----------|----------|------|
| 主配置 | `~/.config/cli-switch/config.yaml` | 不变 | 不变 |
| 自定义模型 | `~/.cli-switch/custom_models.yaml` | `~/.config/cli-switch/custom_models.yaml` | XDG 合规迁移 |
| Hook 配置 | `~/.cli-switch/hooks.yaml` | `~/.config/cli-switch/hooks.yaml` | XDG 合规迁移 |
| Session 数据 | `~/.cli-switch/sessions/` | `~/.local/share/cli-switch/sessions/` | XDG 合规迁移 |
| Lock 文件 | `~/.cli-switch/locks/` | `~/.local/share/cli-switch/locks/` | XDG 合规迁移 |
| Profile 配置 | N/A | `~/.config/cli-switch/profiles.yaml` | **v2.0 新增** |

### 3.2 自动迁移

v2.0 首次运行时会自动检测 v1.x 配置并迁移：

1. 检测 `~/.cli-switch/` 是否存在旧配置
2. 复制到 XDG 标准路径
3. 创建默认 profiles.yaml（基于已有模型推断）
4. 创建 `~/.cli-switch/.migrated` 标记文件
5. 旧文件保留不删除

如需手动迁移：
```bash
# 复制自定义模型
cp ~/.cli-switch/custom_models.yaml ~/.config/cli-switch/

# 复制 Hook 配置
cp ~/.cli-switch/hooks.yaml ~/.config/cli-switch/

# 迁移 Session 数据
mv ~/.cli-switch/sessions/ ~/.local/share/cli-switch/sessions/
```

## 4. JSON 输出变化

### 4.1 所有 JSON 输出新增 `schema_version`

v1.x:
```json
{"current_model": "opus4.6", "tool": "claude-code"}
```

v2.0:
```json
{"schema_version": "2.0.0", "current_model": "opus4.6", "tool": "claude-code"}
```

### 4.2 resolve --json 输出结构

v1.x `env` 命令输出 shell export 语句：
```bash
export ANTHROPIC_MODEL=claude-opus-4-6-20250514
export ANTHROPIC_BASE_URL=https://fucheers.top
export ANTHROPIC_AUTH_TOKEN=sk-xxx
```

v2.0 `resolve --json` 输出完整 RuntimeSpec：
```json
{
  "schema_version": "2.0.0",
  "tool": "claude-code",
  "profile": "default",
  "model": {"key": "opus4.6", "model_id": "..."},
  "auth": {"mode": "api_key", "status": "ready"},
  "command": {"program": "claude", "env_patch": {"ANTHROPIC_MODEL": "..."}},
  "capabilities": {"mcp": true, "skills": true}
}
```

> `env` 命令在 v2.0 中仍然可用，输出格式不变。

## 5. Profile 系统（新概念）

v1.x 中每个工具只有一种配置方式。v2.0 引入 Profile，同一工具可以有多种运行模式。

### 首次使用

v2.0 会为每个工具自动创建 `default` Profile。无需手动配置即可像 v1.x 一样使用。

### 使用 Profile

```bash
# 使用默认 Profile（与 v1 行为相同）
cli-switch opus4.6

# 指定 Profile
cli-switch resolve opus4.6 --profile claude-code/router

# 查看所有 Profile
cli-switch list --profiles
```

## 6. Agent / 脚本迁移

### 6.1 如果你使用 `eval "$(cli-switch env model)"`

**无需改动** — `env` 命令在 v2.0 中完全兼容。

### 6.2 如果你解析 `--json` 输出

需要适配 `schema_version` 字段的新增。建议：
```python
result = json.loads(output)
if result.get("schema_version", "").startswith("2."):
    # v2 格式
else:
    # v1 格式兼容
```

### 6.3 推荐迁移到 resolve --json

`resolve --json` 提供比 `env` 更丰富的信息（auth 状态、能力声明、诊断信息），推荐 Agent 框架迁移。

## 7. Breaking Changes 清单

| 变更 | 影响 | 缓解措施 |
|-----|------|---------|
| 配置文件路径 XDG 化 | 旧路径 `~/.cli-switch/` 中的文件需迁移 | 自动迁移（首次运行） |
| JSON 输出新增 schema_version | 严格 schema 校验的消费者可能报错 | 使用 `result.get()` 而非 `result[]` |
| validate/health-check 废弃 | 依赖这些命令的脚本需更新 | v2.0 仍可用，仅输出警告 |
| 错误码统一 | v1 的 ErrorType 枚举值可能变化 | 使用字符串错误码而非整数 |
