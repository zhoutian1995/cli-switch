# cli-switch v2.0 需求文档

> 版本：v2.0 | 更新日期：2026-04-10 | 状态：需求锁定

## 1. 需求概述

在 v1.2.0（模型切换 + Hooks + MCP + 终端隔离）基础上，v2.0 实现 4 层 Adapter 架构，新增 resolve --json / auth status / doctor / Profile 核心能力。

### 1.1 核心命题验证

| # | 命题 | 验证方式 |
|---|-----|---------|
| 1 | 跨 AI CLI 统一运行时规格可行 | resolve --json 在 5+ 工具上输出一致 schema |
| 2 | 认证问题可结构化诊断 | auth status 准确识别 4 种认证模式 × 6 种状态 |
| 3 | Adapter 架构可扩展 | 新增工具不改核心，< 3 个核心目录变更 |
| 4 | Profile 多模式有价值 | 同一工具 2+ Profile 可正常切换 |

## 2. 命令规格

### 2.1 核心命令（v2.0 新增）

#### `cli-switch resolve [model] [--json] [--profile <name>] [--tool <tool>]`

输出标准化 RuntimeSpec，是 v2.0 的核心命令。

```json
{
  "schema_version": "2.0.0",
  "tool": "claude-code",
  "profile": "default",
  "model": {
    "key": "opus4.6",
    "model_id": "claude-opus-4-6-20250514",
    "vendor": "fucheers",
    "transport": "anthropic-compatible"
  },
  "provider": {
    "id": "fucheers",
    "display_name": "Fucheers",
    "auth_mode": "api_key"
  },
  "auth": {
    "mode": "api_key",
    "status": "ready",
    "source": "env:ANTHROPIC_AUTH_TOKEN"
  },
  "command": {
    "program": "claude",
    "args": [],
    "env_patch": {
      "ANTHROPIC_MODEL": "claude-opus-4-6-20250514",
      "ANTHROPIC_BASE_URL": "https://fucheers.top",
      "ANTHROPIC_AUTH_TOKEN": "sk-****abcd"
    }
  },
  "capabilities": {
    "mcp": true,
    "skills": true,
    "streaming": true,
    "image_input": true,
    "structured_output": true,
    "non_interactive": true
  },
  "diagnostics": []
}
```

#### `cli-switch auth status [--json] [--tool <tool>] [--profile <name>]`

认证状态诊断。

认证模式（auth_mode）：
- `api_key`：API Key 认证
- `login`：CLI 登录态
- `oauth`：OAuth 令牌
- `none`：无需认证

认证状态（status）：
- `ready`：认证就绪
- `missing`：未找到认证凭据
- `expired`：凭据已过期
- `conflict`：多个冲突的认证源
- `unsupported`：工具不支持该认证模式
- `unknown`：无法确定状态

```json
{
  "schema_version": "2.0.0",
  "tool": "claude-code",
  "profile": "default",
  "auth": {
    "mode": "api_key",
    "status": "ready",
    "required": ["ANTHROPIC_AUTH_TOKEN"],
    "detected": [
      {"source": "env:ANTHROPIC_AUTH_TOKEN", "status": "valid"}
    ],
    "hint": null
  }
}
```

#### `cli-switch doctor [--json] [--tool <tool>] [--network]`

统一健康检查。合并 v1.2.0 的 `validate` + `health-check` 功能。

检查项：
1. `binary_found`：AI CLI 二进制是否存在
2. `version_readable`：版本号是否可读取
3. `profile_exists`：Profile 配置是否存在
4. `auth_ready`：认证是否就绪
5. `model_valid`：模型配置是否有效
6. `capability_consistent`：能力声明是否一致
7. `network_reachable`（需 `--network` 标志）：API 端点是否可达

```json
{
  "schema_version": "2.0.0",
  "tool": "claude-code",
  "checks": [
    {"name": "binary_found", "status": "pass", "detail": "/usr/local/bin/claude"},
    {"name": "auth_ready", "status": "fail", "detail": "ANTHROPIC_AUTH_TOKEN not set", "hint": "export ANTHROPIC_AUTH_TOKEN=sk-..."}
  ],
  "summary": {"pass": 5, "fail": 1, "skip": 1}
}
```

### 2.2 保留命令（v1.2.0 兼容）

| 命令 | v1.2.0 行为 | v2.0 变更 |
|-----|-----------|----------|
| `cli-switch <model>` | 切换模型 | 保留，内部通过 Adapter 执行 |
| `cli-switch env <model>` | 输出 export 语句 | 保留，作为 resolve --json 的简化版 |
| `cli-switch list` | 列出模型 | 增加 Profile 信息 |
| `cli-switch status` | 当前状态 | 保留，推荐迁移到 `auth status` |
| `cli-switch test` | HTTP HEAD 测试 | 保留，推荐迁移到 `doctor --network` |
| `cli-switch health-check` | 健康检查 | 废弃预告，迁移到 `doctor` |
| `cli-switch validate` | 配置验证 | 废弃预告，迁移到 `doctor` |
| `cli-switch model *` | 自定义模型管理 | 保留 |
| `cli-switch mcp *` | MCP 管理 | 保留 |
| `cli-switch hook *` | Hook 管理 | 保留 |
| `cli-switch image` | 图片生成 | 保留 |
| `cli-switch chat-test` | 端到端测试 | 保留 |

### 2.3 Profile 系统

Profile 是 v2.0 引入的核心概念，表示同一工具的一种运行配置。

```yaml
# ~/.config/cli-switch/profiles.yaml
profiles:
  claude-code/default:
    tool: claude-code
    description: "默认 Claude Code 配置"
    auth_mode: api_key
    vendor: fucheers
    transport: anthropic-compatible
    capabilities:
      mcp: true
      skills: true

  claude-code/router:
    tool: claude-code
    description: "路由模式 — 通过代理访问"
    auth_mode: api_key
    vendor: custom
    transport: anthropic-compatible
    env_override:
      ANTHROPIC_BASE_URL: "https://my-router.example.com"

  gemini-cli/default:
    tool: gemini-cli
    description: "默认 Gemini CLI 配置"
    auth_mode: login
    vendor: google
    transport: google-ai
```

命名约定：`{tool}/{profile_name}`

## 4. 非功能需求

| 需求 | 规格 |
|-----|------|
| 核心命令延迟（非网络） | ≤300ms |
| JSON 输出格式 | 所有核心命令支持 `--json`，含 `schema_version` |
| 平台支持 | macOS（Apple Silicon/Intel）+ Linux（x86_64/arm64） |
| 路径规范 | XDG Base Directory 合规 |
| 错误输出 | 统一错误码（8 类），含修复建议 |
| 敏感信息 | 自动脱敏（sk-****abcd） |
| 非交互 | 默认非交互模式，适合脚本/Agent 使用 |
| 并发安全 | fcntl flock + 原子写（保留 v1.2.0） |
| 终端隔离 | TTY 级别 Session（保留 v1.2.0） |

## 5. 统一错误码

| 错误码 | 含义 |
|-------|------|
| `CONFIG_NOT_FOUND` | 配置文件不存在 |
| `CONFIG_INVALID` | 配置文件格式错误 |
| `TOOL_NOT_SUPPORTED` | 不支持的工具类型 |
| `MODEL_NOT_FOUND` | 模型不存在 |
| `AUTH_MISSING` | 认证凭据缺失 |
| `AUTH_EXPIRED` | 认证凭据过期 |
| `PROFILE_NOT_FOUND` | Profile 不存在 |
| `ADAPTER_ERROR` | Adapter 内部错误 |

## 7. 接受标准（量化）

1. `resolve --json` 在 4 个工具上输出有效 RuntimeSpec，schema 字段一致性 ≥95%
2. `auth status` 覆盖 4 种认证模式 × 6 种状态
3. `doctor` ≥6 项检查，准确率 ≥80%
4. 新增 Adapter 不改核心目录，变更文件 < 3 个
5. Profile 切换成功率 100%
6. 核心命令延迟 ≤300ms（非网络）
7. v1.2.0 所有保留命令向后兼容
8. macOS + Linux E2E 测试通过
