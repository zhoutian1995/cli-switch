# cli-switch v2.0 架构决策记录（ADR）

> 版本：v2.0 | 更新日期：2026-04-10

本文档采用 ADR（Architecture Decision Record）格式，记录 v2.0 的关键架构决策。

---

## ADR-001: 实现语言 — Python

**状态**：已决策 ✅

**上下文**：
v1.0 文档将实现语言列为开放决策（TypeScript vs Rust），v1.2.0 实际选择了 Python 并成功交付了完整功能。

**选项**：
| 选项 | 优势 | 劣势 |
|-----|------|------|
| Python（当前） | v1.2.0 代码可复用；开发效率高；依赖管理成熟 | 启动速度不如编译语言；无单二进制分发 |
| TypeScript | NPM 生态广；前端团队友好 | 需全部重写；Node 运行时依赖 |
| Rust | 性能最优；单二进制 | 开发周期长；学习曲线陡 |
| Go | 单二进制；CLI 工具生态好 | 需全部重写 |

**决定**：
保持 Python。v1.2.0 已验证的模块（Session/Filelock/Hooks/MCP）可直接迁入 v2.0，风险最低。

**后果**：
- 通过 pip/pipx 分发
- 最低支持 Python 3.8（v1.2.0 已确定）
- 可考虑 PyInstaller 打包单二进制（P2 优先级）

## ADR-002: 配置格式 — YAML（短期）→ TOML（长期）

**状态**：已决策 ✅

**上下文**：
v1.0 文档推荐 TOML，v1.2.0 实际使用 YAML。v2.0 需要向前兼容 v1.2.0 用户配置。

**选项**：
| 选项 | 优势 | 劣势 |
|-----|------|------|
| YAML（当前） | v1.2.0 兼容；嵌套结构友好 | 缩进敏感；隐式类型转换陷阱 |
| TOML | Python 生态标准（pyproject.toml）；类型严格 | 需要迁移工具；深层嵌套可读性差 |
| JSON | 通用；无歧义 | 无注释；手写不友好 |

**决定**：
v2.0 保持 YAML 格式，确保 v1.2.0 配置文件平滑迁移。长期（v2.1+）提供 TOML 支持和自动迁移工具。

**后果**：
- config.yaml / profiles.yaml / custom_models.yaml / hooks.yaml 均保持 YAML
- Registry 加载器需同时支持 YAML 和 TOML（为将来做准备）

## ADR-003: Registry 合并策略 — 对象级合并

**状态**：已决策 ✅

**上下文**：
用户可以在 custom_models.yaml 中覆盖内置模型、在 profiles.yaml 中覆盖默认 Profile。需要定义合并规则。

**决定**：
对象级合并（object-granule merge）：
- 同 key 的对象：用户配置整体替换内置配置
- 不同 key 的对象：合并到同一集合
- 数组字段：不做字段级合并，后者整体替换前者

**示例**：
```yaml
# 内置 default_models.yaml
opus4.6:
  model_id: claude-opus-4-6-20250514
  vendor: fucheers
  tools: [claude-code]

# 用户 custom_models.yaml（整体覆盖 opus4.6）
opus4.6:
  model_id: claude-opus-4-6-20250514
  vendor: my-proxy
  base_url: https://my-proxy.example.com
  tools: [claude-code]
```

## ADR-004: Profile 命名约定 — `{tool}/{name}`

**状态**：已决策 ✅

**上下文**：
Profile 需要全局唯一标识，且能快速关联到所属工具。

**决定**：
`{tool}/{name}` 格式，如 `claude-code/default`、`gemini-cli/router`。

**规则**：
- tool 部分：小写 + 连字符（`claude-code`, `gemini-cli`, `codex-cli`, `opencode`）
- name 部分：小写 + 连字符，≤ 32 字符
- 每个工具必须有一个 `default` Profile
- 保留名：`default`, `router`, `api`

## ADR-005: Doctor 网络检查 — 默认关闭

**状态**：已决策 ✅

**上下文**：
doctor 命令包含本地检查和网络检查。网络检查（API 端点可达性）有延迟且可能触发限流。

**决定**：
- 默认：仅执行本地检查（binary/config/auth/profile）
- `--network` 标志：显式启用网络检查
- 网络检查超时：5 秒

**理由**：
- doctor 应快速可靠（≤300ms 目标）
- 网络问题属于外部因素，与 cli-switch 配置正确性无关
- Agent 场景下频繁调用 doctor 不应产生网络流量

## ADR-006: v1.2.0 功能保留策略

**状态**：已决策 ✅

**上下文**：
v1.2.0 有大量非核心但实用的功能。v2.0 架构重构需要决定哪些保留、哪些废弃。

**决定**：

| 功能 | 策略 | 说明 |
|-----|------|------|
| 模型切换 `cli-switch <model>` | ✅ 保留 | 核心功能，通过 Adapter 重新实现 |
| Agent Mode `env` | ✅ 保留 | 同时提供 `resolve --json` 作为升级版 |
| Hook 引擎 | ✅ 保留 | 迁入横切服务，新增 post_resolve hook |
| MCP 管理 | ✅ 保留 | 作为横切服务 |
| 终端隔离 Session | ✅ 保留 | 扩展记录当前 Profile |
| 并发安全 FileLocker | ✅ 保留 | 不变 |
| 自定义模型 | ✅ 保留 | 迁入 Registry Layer |
| 图片生成 | ✅ 保留 | 作为 GeminiAdapter 能力 |
| 健康检查 `health-check` | ⚠️ 废弃预告 | 迁移到 `doctor --network` |
| 配置验证 `validate` | ⚠️ 废弃预告 | 迁移到 `doctor` |
| `status` 命令 | ⚠️ 废弃预告 | 迁移到 `auth status` |
| `chat-test` 命令 | ✅ 保留 | 独立功能，不受架构影响 |

废弃预告策略：v2.0 中旧命令仍可用，输出 deprecation warning + 迁移提示，v2.1 移除。

## ADR-007: Adapter Contract Test — 必选

**状态**：已决策 ✅

**上下文**：
Adapter 架构的核心价值在于接口统一。需要强制验证每个 Adapter 正确实现了协议。

**决定**：
每个 Adapter 必须通过统一的 contract test：
1. 实现所有 7 个必选方法
2. `resolve_model` 返回合法 Model 对象
3. `resolve_auth` 返回合法 AuthResult 结构
4. `build_command` 返回非空 program + 可预览命令
5. `doctor_checks` 返回 ≥1 项检查结果
6. 所有返回值通过 schema 验证

新增 Adapter 的 PR 必须包含 contract test 通过证明。

## ADR-008: schema_version 策略

**状态**：已决策 ✅

**上下文**：
所有 JSON 输出需要包含 schema_version，用于机器消费者判断兼容性。

**决定**：
- 格式：SemVer（`major.minor.patch`）
- v2.0 初始版本：`"2.0.0"`
- 版本变更规则：
  - **major**：移除字段、改变字段类型（breaking）
  - **minor**：新增字段、新增枚举值（non-breaking）
  - **patch**：修复描述/文档（no schema change）

**后果**：
- 所有 JSON 输出的顶层包含 `schema_version` 字段
- 消费者可根据 major 版本判断兼容性
- 字段变更需走 schema review 流程
