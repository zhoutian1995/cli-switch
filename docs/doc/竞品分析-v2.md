# cli-switch v2.0 竞品分析

> 版本：v2.0 | 更新日期：2026-04-10

## 1. 市场背景

2025-2026 年 AI CLI 工具爆发式增长，开发者同时使用 3-5 个 AI CLI 工具已成常态。核心痛点：

- 模型切换需手动改配置文件
- 认证状态分散在各工具私有配置中，出错难以诊断
- Agent 框架需要标准化运行时规格，各工具输出格式不统一
- 多终端并发使用时配置互相覆盖

## 2. 竞品矩阵

### 2.1 直接竞品

| 产品 | 类型 | 核心能力 | 局限 |
|-----|------|---------|------|
| **claude-code-router** | Claude Code 增强 | Claude Code 路由层，多模型支持 | 仅限 Claude Code；无跨工具能力 |
| **cc-switch** | 桌面管理器 | GUI 模型切换，可视化管理 | 桌面应用，不支持 Agent 集成 |
| **cc-switch-cli** | CLI 管理器 | 命令行模型切换 | 仅 Claude Code；无 resolve/auth 标准化 |
| **9router** | 本地网关 | 本地 API 代理，请求路由 | 代理架构（侵入性高）；不做诊断 |

### 2.2 间接竞品 / 相邻工具（v2.0 新增分析）

| 产品 | 类型 | 与 cli-switch 的关系 |
|-----|------|-------------------|
| **OpenCode** | 终端 AI 编码工具 | 竞争 + 适配目标（v2.0 新增 Adapter） |
| **Cursor** | AI IDE | 不同赛道（IDE vs CLI），但用户重叠 |
| **Continue.dev** | IDE AI 插件 | 开源，VS Code/JetBrains 集成，用户可能同时使用 CLI |
| **Aider** | 终端 AI 编码 | Git-aware AI 编码，CLI 形态竞品 |
| **Cline** | VS Code AI 插件 | IDE 内 Agent，非 CLI 形态 |
| **litellm** | API 代理层 | API 级别路由/代理，与 cli-switch 的 CLI 运行时适配定位不同 |

### 3.2 独特卖点（v2.0）

1. **唯一做 RuntimeSpec 标准化的 CLI 工具** — `resolve --json` 输出跨工具统一格式，Agent 框架可直接消费
2. **唯一提供认证诊断的** — `auth status --json` 覆盖 login/api_key/oauth/none 四种模式
3. **唯一支持 Profile 多运行模式的** — 同一工具可配置多个 Profile，切换不同运行策略
4. **Adapter 架构可扩展** — 新增工具只需一个 Adapter 文件，核心不改
5. **终端隔离 + 并发安全** — 多 Agent 并发使用，TTY 级别隔离

## 4. 市场定位声明

> cli-switch 是**AI CLI 运行时编排的结构化公共层**。
> 不是更多的管理 UI，不是 API 代理网关，不是大模型聚合器。
> 核心交付：**标准化 RuntimeSpec + 结构化诊断 + 可扩展 Adapter**。

## 5. cli-switch 不做什么（与竞品边界）

| 不做 | 原因 | 谁在做 |
|-----|------|-------|
| 桌面控制台 | 定位 CLI + Agent，不做 GUI | cc-switch |
| 本地 API 代理 | 不拦截/代理 API 请求 | 9router, litellm |
| 50+ 供应商聚合 | 少量高质量 > 大而全 | litellm |
| IDE 插件 | CLI 工具层，不侵入 IDE | Cursor, Continue, Cline |
| 单 CLI 深度优化 | 跨工具适配层，不替代原生 CLI | claude-code-router |

## 6. 竞争策略

### 短期（v2.0）
- 巩固 CLI 运行时编排的唯一定位
- 通过 resolve --json + auth status 建立标准化壁垒
- 支持 5+ AI CLI，形成网络效应

### 中期
- 建立 Adapter 生态（社区贡献新工具 Adapter）
- 与 Agent 框架深度集成（LangChain / CrewAI / AutoGen 等）
- Profile 模板市场

### 长期
- 成为 AI CLI 生态的"运行时标准层"
- schema_version 演进为社区标准
