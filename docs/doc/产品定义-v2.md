# cli-switch v2.0 产品定义

> 版本：v2.0 | 更新日期：2026-04-10 | 状态：规划中

## 1. 产品定位

cli-switch 是**多 AI CLI 运行时编排层**（Runtime Orchestration Layer），为 Agent 和高级 CLI 工作流提供统一的模型选择、认证诊断、运行时规格输出能力。

**cli-switch 不是**：新的 AI CLI、本地代理网关、桌面管理界面。
**cli-switch 是**：适配器层，统一解析、诊断、适配，输出标准化 JSON。

## 2. v1.2.0 → v2.0 演进

### v1.2.0 已实现能力
- 模型切换：Claude Code / Gemini CLI / Codex CLI（20+ 内置模型）
- Agent Mode：`cli-switch env` 零副作用环境变量输出
- MCP Server 管理：ZAI 视觉、web-search、web-reader
- Hook 引擎：post_switch / pre_tool_use / post_tool_use
- 终端隔离：TTY 级别 Session + PID 验证
- 并发安全：fcntl flock + 原子写
- 自定义模型：custom_models.yaml 覆盖
- 健康检查：HTTP HEAD + 缓存
- 图片生成：Gemini API
- 错误诊断：9 类错误分类 + 修复建议

### v2.0 新增能力
- **resolve --json**：标准化 RuntimeSpec 输出（含 schema_version）
- **auth status --json**：认证状态诊断（ready/missing/expired/conflict）
- **doctor**：统一健康检查命令
- **Profile 系统**：同一工具多运行模式
- **4 层 Adapter 架构**：CLI → Core Resolver → Adapter → Registry
- **更多 AI CLI 支持**：OpenCode、Cursor、Continue.dev 等

## 3. 目标用户

| 用户类型 | 核心诉求 | 使用场景 |
|---------|---------|---------|
| Agent 框架作者 | 标准化运行时规格 + 零副作用切换 | `resolve --json` 获取 RuntimeSpec，程序化选择模型 |
| 高级 CLI 用户 | 快速切换模型 + 多工具管理 | 终端内 `cli-switch opus4.6` 一键切换 |
| AI CLI 集成开发者 | 统一认证诊断 + 适配器扩展 | `auth status --json` 检查认证，编写新 Adapter |
| DevOps / 平台工程师 | 多环境配置管理 + 健康监控 | `doctor --json` 自动化巡检 |

## 4. 核心价值主张

### 4.1 标准化 RuntimeSpec
所有 AI CLI 工具通过 `resolve --json` 输出统一的 RuntimeSpec JSON：
- 模型信息（model_id / vendor / transport）
- 认证状态（auth mode / status）
- 命令规格（program / args / env_patch）
- 能力声明（mcp / skills / streaming / image_input）
- schema_version 版本控制

### 4.2 Adapter 可扩展性
每个 AI CLI 一个 Adapter，核心 Resolver 无需感知工具差异：
- 新增工具 = 新增一个 Adapter 文件
- 核心目录零修改
- 统一 contract test 验证

### 4.3 Profile 多模式
同一工具支持多种运行配置：
- `claude-code/default`：默认配置
- `claude-code/router`：路由模式
- `claude-code/api`：API-only 模式

### 4.4 诊断优先
- `auth status`：主动发现认证问题
- `doctor`：全面健康检查
- 结构化错误码 + 修复建议

## 5. 产品原则

| 原则 | 说明 |
|-----|------|
| **JSON-First** | 所有核心命令必须支持 `--json`，输出含 `schema_version` |
| **Adapter-First** | 工具差异封装在 Adapter 内，核心不感知 |
| **Profile-First** | 运行配置通过 Profile 显式建模，不依赖隐式环境变量堆叠 |
| **诊断优先** | 出错时给出结构化错误码和修复建议，不输出裸文本错误 |
| **零副作用可选** | Agent 场景下 `env` / `resolve` 不修改任何文件 |

## 6. 产品红线（不做什么）

1. 不做桌面 UI 或控制台
2. 不做本地代理网关（不代理 API 请求）
3. 不做 50+ 模型供应商的大集合
4. 不做自动故障转移 / 轮询路由
5. 不做费用追踪仪表盘
6. 不做自动登录 / OAuth 流程
7. 不做远程配置中心
8. 不做团队 RBAC 权限管理
9. 不做 skills/MCP 市场
10. 不替代原生 AI CLI
