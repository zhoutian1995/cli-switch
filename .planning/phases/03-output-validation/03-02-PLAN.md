  <name>Task 1: Implement unified diff parser and path validator</name>
  <files>src/core/validation/diff-validator.ts</files>
  <read_first>src/types/capability.ts, docs/specs/sandbox-spec.md</read_first>
  <action>Create `src/core/validation/diff-validator.ts`:
  - `DiffFile { path: string; hunks: DiffHunk[] }`
  - `DiffHunk { header: string; oldStart: number; oldCount: number; newStart: number; newCount: number; lines: string[] }`
  - `DiffParseResult { valid: boolean; files: DiffFile[]; errors: string[] }`
  - `parseUnifiedDiff(diffText: string): DiffParseResult`
    - Split by `diff --git` headers.
    - Extract path from `--- a/path` line (strip `a/` prefix).
    - Parse `@@ -oldStart,oldCount +newStart,newCount @@` headers.
    - Handle edge cases: empty diff, binary files, no newline at EOF markers.
  - `ProtectedPathConfig { paths: string[] }` with defaults `[".git/", "node_modules/", ".env"]` (plus glob patterns like `*.lock`).
  - `validateDiffPaths(files: DiffFile[], config?: ProtectedPathConfig): { violations: string[]; clean: boolean }`
    - Check each file path against protected paths.
  - Export from barrel.</action>
  <verify>npx vitest run test/unit/diff-validator.test.ts</verify>
  <acceptance_criteria>
    - `parseUnifiedDiff("diff --git a/src/foo.ts b/src/foo.ts\n--- a/src/foo.ts\n+++ b/src/foo.ts\n@@ -1,1 +1,2 @@\n-old\n+new\n+extra\n")` returns `{ valid: true, files: [{ path: "src/foo.ts", hunks: [{...}] }] }`.
    - Empty string returns `{ valid: false, errors: ["Empty diff"] }`.
    - `validateDiffPaths([{ path: ".git/config" }])` returns `{ clean: false, violations: [".git/config matches protected path .git/"] }`.
  </acceptance_criteria>
  <done>Diff parser and path validator are implemented.</done>
</task>

<task type="auto">
  <name>Task 2: Implement bounded auto-repair pipeline</name>
  <files>src/core/validation/repair.ts</files>
  <read_first>src/core/validation/validator.ts, src/core/validation/diff-validator.ts</read_first>
  <action>Create `src/core/validation/repair.ts`:
  - `RepairConfig { maxAttempts: number; maxTotalRepairs: number }` with defaults `{ maxAttempts: 2, maxTotalRepairs: 3 }`.
  - `RepairResult { success: boolean; output: string; attempts: number; repairs: string[] }`
  - `repairOutput(capability: CapabilityId, rawOutput: string, config?: RepairConfig): RepairResult`
    - Attempt 1: If output contains JSON embedded in text (e.g., "Here's the result: {...}"), extract JSON via regex `/\\{[\\s\\S]*\\}/`.
    - Attempt 2: If output contains diff-like content, extract diff blocks via regex for `diff --git` sections.
    - Track total repairs across strategy execution via module-level counter (reset per strategy run).
    - Return `{ success: false }` if budget exhausted.
  - `resetRepairCounter(): void` — call at strategy start.
  - Export from barrel.</action>
  <verify>npx vitest run test/unit/repair.test.ts</verify>
  <acceptance_criteria>
    - `repairOutput('write_code', 'Here is the result:\n```json\n{"status":"success","summary":"done","files_changed":["a.ts"],"diff":"..."}\n```')` extracts the JSON successfully.
    - `repairOutput('write_code', 'No JSON here')` returns `{ success: false }` after all attempts.
    - Repair counter increments across calls and `resetRepairCounter()` clears it.
  </acceptance_criteria>
  <done>Auto-repair pipeline with bounded budget is implemented.</done>
</task>

  - Import `validateOutput` from `../validation/validator.js` and `repairOutput` from `../validation/repair.js`.
  - After each step executor call, call `validateOutput(step.capability, result.output)`:
    - If valid: store `validatedOutput` in `StepHistory`.
    - If invalid: call `repairOutput()`. If repair succeeds, re-validate. If still invalid, store raw output and add a validation warning to errors (don't fail the step — agent output issues shouldn't abort the strategy).
  - Call `resetRepairCounter()` at the start of `executeStrategy()`.
  - Add `validatedOutputs?: Record<string, unknown>` to `StrategyResult` — a map of `"step-{N}" → validatedOutput`.
  - Do NOT add validation to the single-step fast path or `runSingle()` — only multi-step strategy execution.</action>

  <acceptance_criteria>

    - Multi-step strategy with invalid output attempts repair before giving up.
    - Single-step strategy is unaffected.
    - StrategyResult includes `validatedOutputs` when validation succeeds.
  </acceptance_criteria>
  <done>Strategy engine validates and repairs output after each step.</done>
