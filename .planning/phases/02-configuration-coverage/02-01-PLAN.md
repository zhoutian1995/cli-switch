1. Root CliSwitchConfig interface covering the sections needed by Phase 2:
   - gateway: { api_key?, base_url?, models?, default_tier?, agent_keys? } — mirrors GatewayConfig shape but all optional (user config fills gaps, env fills more gaps).
   - routing: { tier_default?, capability_tier_override? } — mirrors RoutingConfig.

3. EffectiveConfig interface: merged result with source metadata (global/project loaded status).
4. ConfigLoadResult: { config: EffectiveConfig | null, errors: ConfigError[] }.

Use Zod for schema validation (zod is already a dependency). Define a configSchema that validates:
- Known top-level sections only (gateway, routing, execution, loop, output).
- tier values must be one of 'economy' | 'standard' | 'premium'.
- default_strategy must be a valid StrategyName if present.
- api_key and agentKeys values must be non-empty strings if provided.
- Reject unknown top-level keys with a warning path (or strict rejection — agent's discretion).

Export both TypeScript interfaces and the Zod schema.
</action>

  <action>Implement config loading:

1. Add a YAML parser. Options:
   - Use js-yaml (add dependency) — mature, widely used.
   - Use a small inline YAML subset parser — no new dependency.
   Agent's discretion; js-yaml is recommended for correctness.

2. loadConfig(cwd?: string): ConfigLoadResult
   - Resolves global path: resolvePaths().configDir + '/config.yaml'.
   - Resolves project path: (cwd ?? process.cwd()) + '/.cli-switch.yaml'.
   - Reads each file if it exists; missing files are not errors.
   - Parses YAML; invalid YAML produces a CONFIG_INVALID error in the result.
   - Validates each parsed object against the Zod schema.
   - Deep-merges project over global (global is base, project overrides).
   - Returns merged config + source metadata + any errors.

3. Export from src/core/config/index.ts barrel.

Follow decisions D-01 through D-04 from the context doc.
</action>
  <verify>npm run build</verify>
  <acceptance_criteria>

    - Missing files produce no errors.
    - Invalid YAML produces CONFIG_INVALID error.
    - Invalid schema (wrong tier, unknown section) produces CONFIG_INVALID error.
  </acceptance_criteria>
  <done>Config loader reads global + project YAML, validates, and merges.</done>
</task>
