1. Key path grammar: dot-separated, e.g.:
   - `gateway.base_url` → config.gateway.base_url
   - `gateway.models.economy` → config.gateway.models.economy
   - `routing.tier_default` → config.routing.tier_default
   - `routing.capability_tier_override.write_code` → config.routing.capability_tier_override.write_code
   - `execution.default_strategy` → config.execution.default_strategy
   - `loop.max_iterations` → config.loop.max_iterations

2. Value handling:
   - Strings are stored as-is.
   - Numeric values (detectable) are stored as numbers.
   - Boolean strings ('true'/'false') stored as booleans.
   - Nested key creation: if intermediate objects don't exist, create them.

3. Target:
   - Default: global config (resolvePaths().configDir + '/config.yaml').
   - With --project: cwd + '/.cli-switch.yaml'.

4. Write behavior:
   - Read existing YAML file (or start with empty object if not exists).
   - Set the value at the dot-path.
   - Validate the resulting config against the Zod schema.
   - If validation fails, reject with CONFIG_INVALID error, do not write.
   - Write back as YAML.

5. Output:
   - Text: "Set gateway.base_url = https://..." in global/project config.
   - JSON: printJson with { ok: true, data: { key, value, target, path } }.

Follow decisions D-15 (global default, --project flag), D-21 (CONFIG_WRITE_FAILED, CONFIG_INVALID, CONFIG_KEY_NOT_FOUND).
</action>

  <action>Add `config reset [key] [--all] [--project] [--json]`:

1. Single key reset: `config reset gateway.base_url`
   - Remove the key from the target config file.
   - If key doesn't exist, return CONFIG_KEY_NOT_FOUND warning (not error).
   - If removing the key empties a parent object, optionally clean up empty objects.
   - Write back modified YAML.

2. Full reset: `config reset --all`
   - Requires explicit --all flag (D-16).
   - Deletes the entire config file (or truncates to empty object).
   - Should prompt "Are you sure?" in text mode. In --json mode, just do it (machine caller knows what it's doing).
   - Actually, since cli-switch doesn't have interactive prompts for destructive ops in other commands, just require --all and do it. Add a warning.

3. Target:
   - Default: global config.
   - With --project: project config.

4. Output:
   - Text: "Reset gateway.base_url in global config" or "Reset all global configuration".
   - JSON: printJson with { ok: true, data: { key?, target, path } }.

Follow decisions D-16 (conservative reset), D-21 (error codes).
</action>
