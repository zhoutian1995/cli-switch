<task type="auto">
  <name>Task 2: Create skill command with run/list/show subcommands</name>
  <files>cmd/skill.ts, cmd/root.ts</files>
  <read_first>cmd/run.ts, cmd/root.ts, cmd/config.ts, src/core/skill/loader.ts, src/core/skill/schema.ts</read_first>
  <action>Create `cmd/skill.ts` and register in `cmd/root.ts`:

  **`skill list [--json]`**:
  - Call `listSkills(projectDir)` where projectDir is current working directory or `--project` flag.
  - Print table: Name | Source | Description (default), or JSON array if `--json`.
  - Exit 0 even if no skills found (print "No skills found.").

  **`skill show <name> [--json]`**:
  - Call `loadSkill(name, projectDir)`.
  - Print formatted skill definition or JSON if `--json`.
  - Exit 1 if skill not found or invalid, with error message.

  **`skill run <name> [input...]`**:
  - Call `loadSkill(name, projectDir)`. Exit 1 if not found/invalid.
  - Resolve defaults: capability from skill, strategy from skill or config `skills.default_strategy`, tier from skill or config `skills.default_tier`.
  - Render prompt: if skill has prompt_template, use renderPrompt(skill, input). Otherwise use input as-is.
  - Delegate to existing run pipeline: import and call the core run logic from cmd/run.ts (extract runAgent or similar if needed, or replicate the key steps).
  - Support flags: --execution-mode, --tier, --strategy (override skill defaults), --dry-run, --patch-apply, --keep-temp, --merge-worktree.
  - Print resolved parameters at start (like run command does).

  **Register in root.ts**:
  - Add `skill` command with description "Manage and run skill workflows".

  Implementation notes:
  - Study `cmd/run.ts` carefully for the execution pipeline. Reuse as much as possible.
  - If cmd/run.ts has a function you can import, import it. If the logic is inline, extract it.
  - The skill run command should feel like a wrapper around `cli-switch run --capability <X> --strategy <Y> --tier <Z>`.
  - Use the same output formatting (console.log/error, spinner patterns, etc.) as run.ts.</action>
  <verify>npx vitest run test/unit/cmd-skill.test.ts</verify>
  <acceptance_criteria>
    - `cli-switch skill list` prints a table of skills (or "No skills found.").
    - `cli-switch skill show bug-fix` prints skill details.
    - `cli-switch skill run bug-fix "fix login"` resolves capability/strategy/tier from skill definition.
    - `cli-switch skill run nonexistent "input"` exits with error.
  </acceptance_criteria>
  <done>Skill commands are functional.</done>
</task>
