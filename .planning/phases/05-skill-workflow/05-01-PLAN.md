<task type="auto">
  <name>Task 1: Define skill Zod schema and TypeScript types</name>
  <files>src/core/skill/schema.ts</files>
  <read_first>src/types/capability.ts, src/types/strategy.ts, src/types/gateway.ts</read_first>
  <action>Create `src/core/skill/schema.ts`:
  - `SkillDefinition { name: string, description: string, capability: CapabilityId, strategy?: StrategyName, tier?: Tier, prompt_template?: string, execution_mode?: ExecutionMode, env?: Record<string, string> }`
  - Zod schema with strict validation (no unknown keys):
    - `name`: z.string().min(1)
    - `description`: z.string().min(1)
    - `capability`: z.enum([...CAPABILITY_IDS])
    - `strategy`: z.enum(["single", "write_review", "write_test_fix", "high_quality"]).optional()
    - `tier`: z.enum(["economy", "standard", "premium"]).optional()
    - `prompt_template`: z.string().optional()
    - `execution_mode`: z.enum(["default", "patch-only", "temp-copy", "worktree"]).optional()
    - `env`: z.record(z.string(), z.string()).optional()
  - `SkillInfo { name: string; description: string; source: "global" | "project" }` — for listing.
  - `SkillLoadError { code: string; message: string; path?: string }`
  - Export `skillSchema`, `SkillDefinition`, `SkillInfo`, `SkillLoadError`, `validateSkillYaml(obj: unknown)` function.</action>
  <verify>node -e "..." or npx vitest run test/unit/skill-schema.test.ts</verify>
  <acceptance_criteria>
    - `skillSchema.parse({ name: "test", description: "A test", capability: "write_code" })` succeeds.
    - `skillSchema.parse({ name: "test", description: "A test", capability: "invalid" })` fails.
    - Unknown keys are rejected (strict mode).
  </acceptance_criteria>
  <done>Skill schema is defined with Zod validation.</done>
</task>

<task type="auto">
  <name>Task 2: Implement skill loader</name>
  <files>src/core/skill/loader.ts</files>
  <read_first>src/core/config/loader.ts, src/platform/paths.ts, src/core/skill/schema.ts</read_first>
  <action>Create `src/core/skill/loader.ts`:
  - `SkillLoadResult { skill: SkillDefinition | null; source: "global" | "project" | null; errors: SkillLoadError[] }`
  - `getSkillDirs(projectDir?: string): { project: string; global: string }`
    - Project: `<projectDir>/.cli-switch/skills/`
    - Global: `<XDG config dir>/cli-switch/skills/` (use resolvePaths from platform/paths.ts)
  - `loadSkill(name: string, projectDir?: string): Promise<SkillLoadResult>`
    - Look for `<name>.yaml` in project skills dir first, then global.
    - Read file, parse YAML (use js-yaml: `import * as yaml from 'js-yaml'; yaml.load(text)`).
    - Validate with skillSchema.
    - Return skill definition or errors.
  - `listSkills(projectDir?: string): Promise<SkillInfo[]>`
    - Scan both directories for `.yaml` files.
    - Parse name and description from each (partial parse — just read name and description fields).
    - Return sorted list with source indicator.
  - Export from barrel.</action>
  <verify>npx vitest run test/unit/skill-loader.test.ts</verify>
  <acceptance_criteria>
    - `loadSkill("bug-fix", projectDir)` finds `.cli-switch/skills/bug-fix.yaml` in the project dir.
    - Project skill overrides global skill with same name.
    - `loadSkill("nonexistent")` returns `{ skill: null, errors: [{ code: "SKILL_NOT_FOUND" }] }`.
    - `listSkills()` returns all discovered skills with source info.
  </acceptance_criteria>
  <done>Skill loader searches and validates skill definitions.</done>
</task>
